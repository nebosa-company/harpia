# Documentation style guide

These rules are checked mechanically before a page is published. They are
deliberately narrow: each one is either true of a page or it is not.

1. **Sentence case headings.** In every heading, only the first word and
   words on the proper-noun list below begin with a capital letter.
2. **Line length.** No line in the file is longer than 80 characters.
3. **Second person.** The reader is addressed as "you". The words "we",
   "our" and "us" never appear, and neither does the phrase "the user".
4. **No exclamation marks.** Anywhere.
5. **Fenced code blocks declare a language.** The opening fence is
   followed immediately by a language tag, for example ```` ```bash ````.
6. **Product name.** Outside code, the product is written `Kestrel Sync`
   exactly — never lower-cased, hyphenated, run together, or replaced by
   a vague phrase such as "the tool".
7. **No contractions.** Write "do not", "cannot", "it is", "you will".
   The banned forms are: don't, doesn't, didn't, can't, won't, isn't,
   aren't, wasn't, it's, you're, you'll, you've, we're, let's, that's,
   there's.
8. **Ordered lists.** Every item in an ordered list is written `1.`; the
   renderer numbers them.
9. **Whitespace.** No line ends in a space or a tab, and the file ends
   with exactly one newline.

## Proper-noun list

Words that may keep their capital letter anywhere in a heading:

Kestrel, Sync, Windows, macOS, Linux, Python, Docker, JSON, YAML, CSV,
API, CLI, SSH, HTTP.

Everything not on this list is lower-cased unless it is the first word of
the heading.
