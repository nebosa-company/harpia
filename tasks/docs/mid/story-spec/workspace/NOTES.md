# Specification notes

The spec is what the build is reviewed against, so it has to be
traceable in both directions: from a story to the requirements it
produced, and from a requirement back to the story that asked for it.
A requirement nobody asked for is the most expensive kind.

Rejected stories keep their numbers so that older meeting notes still
resolve. They are not scope.
