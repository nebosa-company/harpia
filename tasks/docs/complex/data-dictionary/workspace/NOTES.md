# Data dictionary notes

Three artefacts describe this schema and none of them is complete on its
own. The DDL knows the types and the constraints, the notes know what
the columns mean, and the sample extracts show what the values actually
look like. The dictionary is the document that puts all three in one
place, which is why analysts read it instead of the schema.

The part that matters most is honesty about the gaps. A column with no
note gets said so rather than getting a description invented for it: the
whole point of the document is that a reader can trust the descriptions
that are there.
